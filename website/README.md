# MacQ website

The marketing site for [MacQ](../README.md), served at
[macq.birju.dev](https://macq.birju.dev). Astro, static output, and about a
kilobyte of JavaScript for one carousel gesture.

## Develop

```sh
cd website
npm install
npm run dev      # http://localhost:4321
```

| Script            | What it does                                      |
| ----------------- | ------------------------------------------------- |
| `npm run dev`     | Dev server with hot reload                        |
| `npm run build`   | Type-check, then build static output into `dist/` |
| `npm run preview` | Serve `dist/` locally, exactly as deployed        |
| `npm run og`      | Re-render `public/og.png` from `scripts/og.html`  |

## Layout

One screen, stacked top to bottom: header, hero copy, a horizontal carousel of
app shots, then the feature list. The carousel absorbs whatever vertical space
is left over, which parks it in the middle of the window and keeps the features
pinned to the bottom. Below 900px the gutters and tiles shrink, and below 600px
the type scales down with them.

The carousel is the browser's own horizontal scrolling. Nothing snaps or pages:
a flick keeps its momentum and stops where it runs out. The strip runs the full
width of the window with its edges masked to a fade, and it carries `tabindex`
so the arrow keys drive it for anyone without a trackpad.

The one script on the site lives in
[Screenshots.astro](src/components/Screenshots.astro) and covers the gestures a
mouse does not have: click-and-drag to pan, with a decaying glide on release,
and a vertical wheel mapped onto the strip's horizontal axis. Trackpad and touch
are deliberately left to the browser, which already does both better. With the
script blocked the page still renders and the strip still scrolls.

```
src/
  site.config.ts        all the copy: headline, features, version, links
  lib/shots.ts          reads public/shots/ at build time
  layouts/Base.astro    <head>, meta tags, global stylesheet
  components/
    SiteHeader.astro    app icon, wordmark and the two nav pills
    Hero.astro          headline, download button, caption
    Screenshots.astro   the horizontal carousel of shots
    Shot.astro          one tile: video, image or placeholder
    Features.astro      the list under the carousel
    BrandMark.astro     the Q glyph, watermarked onto placeholder tiles
    AppleGlyph.astro    Apple logo on the download button
  styles/global.css     every rule on the page
public/                 copied into dist/ verbatim, dotfiles included
  shots/                carousel images, see its README
  app_icon.png          the header logo, resized from the app's AppLogo asset
  favicon.png           generated from the app icon
  og.png                generated by npm run og
  CNAME                 the custom domain, read by Pages from the artifact
  .nojekyll             stops Pages running the output through Jekyll
screenshots/            full-resolution shot originals, not shipped
```

## Updating for a release

Change `version` in [src/site.config.ts](src/site.config.ts). The download URL
is built from it and follows the Makefile's `MacQ-<version>.dmg` naming and the
untagged-`v` release tags already on GitHub. Drop `releaseStage` to `null` when
MacQ is no longer alpha.

## Screenshots

The carousel reads whatever is in [public/shots/](public/shots/), sorted by
filename, and falls back to placeholder tiles when the folder is empty. The
filename becomes the alt text, so name the files for what they show. See
[public/shots/README.md](public/shots/README.md) for naming, formats and how
the shipped WebP files are generated from the originals.

## Deploy

[.github/workflows/website.yml](../.github/workflows/website.yml) builds this
directory and publishes `dist/` to GitHub Pages. It runs on pushes to `main`
that touch `website/`, on published releases, and on demand from the Actions
tab. There are no secrets: the deploy authenticates with the workflow's own
OIDC token.

The push trigger is filtered to `website/**` because the macOS app shares this
repository and is committed to far more often than the site. Drop the `paths:`
filter to redeploy on every push to `main`.

Two things have to be set up once, and only once:

1. **Settings > Pages > Build and deployment > Source: "GitHub Actions".**
   Until this is switched over, the deploy step fails with a 404 from the Pages
   API.
2. **DNS: a `CNAME` record for `macq` pointing at `birjuvachhani.github.io`.**
   The domain itself is committed at [public/CNAME](public/CNAME), because an
   Actions-based deploy serves whatever is in the artifact and would otherwise
   drop the custom domain on the first run.

`npm run build` writes a fully static `dist/` with no server runtime, so any
other static host works too: build command `npm run build`, output directory
`dist`.
